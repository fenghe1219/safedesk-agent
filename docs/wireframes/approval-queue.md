# 审批队列布局底稿

> 页面：`/approvals`  
> 目标：让审批人在最短时间内判断“发生了什么、会改什么、风险多大、是否可恢复”  
> 视觉规范：`docs/design-system.md`

## 1. 桌面布局

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ SafeDesk   工作台  工单  审批  知识  评估  审计  看板       演示身份  陈审批 ▾ │ 56
├──────────────────────────────────────────────────────────────────────────────┤
│ 审批队列                                            [全部风险 ▾] [待处理 ▾]   │ 72
│ 3 项待处理 · 1 项将在 5 分钟内过期                                           │
├──────────────────────────────────────────────────────────────────────────────┤
│ 风险   动作                    申请人    影响对象        等待     有效期      │
│ ──────────────────────────────────────────────────────────────────────────── │
│ 高风险 重置 VPN 证书           林晓      林晓 / 本人     07:42    00:05:18    │
│ 高风险 授予应用访问权限        周明      周明 / 财务部   03:10    00:11:42    │
│ 低风险 查询 VPN 状态           林晓      林晓 / 本人     01:20    —           │
│                                                                              │
│ 说明：只读动作自动执行；此处仅显示需要人工决定的写操作。                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 2. 页面头部

- 标题 20px/600，右侧为风险、状态、时间范围筛选。
- 摘要行使用 13px 次要文字：待处理数量、临期数量、最近刷新时间。
- 不显示“审批通过率”等运营指标；这些放在看板。
- 自动刷新通过 Case 事件订阅或短轮询实现，刷新时保持滚动位置。

## 3. 队列列表

### 3.1 列设计

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 风险 | 高风险 / 中风险 / 低风险 | 图标 + 文字，不只靠颜色 |
| 动作 | 人类可读动作名 + 工具名（次要） | 例如“重置 VPN 证书” |
| 申请人 | 姓名 + 部门 | 不展示申请人的敏感信息 |
| 影响对象 | 人/系统/范围 | 多人影响时显示“3 人”并可展开 |
| 等待时长 | 相对时间 | 悬停显示开始时间 |
| 有效期 | 倒计时 | 5 分钟内标临期 |
| 状态 | 待处理 / 已批准 / 已拒绝 / 已过期 | 默认只显示待处理 |

### 3.2 排序

默认排序：风险等级降序 → 剩余有效期升序 → 等待时长降序。

支持切换：最近请求、最早请求、风险等级。筛选条件写入 URL。

### 3.3 行交互

- 单击行打开右侧详情抽屉。
- 键盘上下移动选中行，Enter 打开。
- 临期行使用浅琥珀底 + 时钟图标 + “剩余 05:18”，不使用闪烁。
- 已过期行保留在“全部”中，状态明确，不提供批准按钮。

## 4. 详情抽屉

宽度 560–600px，右侧滑出，头部与底部固定，中间滚动。

### 4.1 信息顺序

1. 动作与风险
2. 申请人和影响对象
3. Agent 理由与证据
4. 工具参数
5. 风险与副作用
6. 验证与回滚
7. 审批历史
8. 决定区

### 4.2 参数展示

- 先用人类可读摘要，再提供“查看技术参数”展开。
- 参数键使用等宽字体；值按类型格式化。
- 隐藏密码、Token、密钥等敏感值，只显示“已脱敏”。
- 显示参数哈希的短形式，允许复制完整值。

### 4.3 证据展示

- 每条证据显示来源、时间、摘要和“查看原文”。
- 证据不足时在理由区明确说明，不把审批材料做成“看起来完整”。
- 证据与参数变化后，抽屉提示“材料已更新，请重新确认”。

## 5. 决定交互

### 5.1 批准二次确认

```text
┌────────────────────────────────────────────┐
│ 确认批准并执行？                           │
│                                            │
│ 动作：重置 VPN 证书                        │
│ 影响：林晓（user_1024）                    │
│ 风险：高风险                               │
│ 有效期：2026-11-03 09:45                   │
│                                            │
│ 批准后流程将立即恢复并执行一次。            │
│                                            │
│ [取消]                  [确认批准并执行]   │
└────────────────────────────────────────────┘
```

- 主按钮使用主色，不使用红色；“拒绝”才是 Danger 次操作。
- 批准按钮在请求中显示进度并禁用，防止双击。
- 并发审批冲突时显示“该动作已由陈审批处理”，刷新抽屉。

### 5.2 拒绝

- 原因必填，最少 5 个字符。
- 提供常用原因：信息不足、影响对象不符、风险过高、需走人工流程。
- 拒绝后显示“已拒绝”，并提供“转工单”或“返回队列”。

### 5.3 过期

- 倒计时归零后，批准按钮立即禁用。
- 显示“审批已过期”，提供“重新发起审批”路径（若 Case 允许）。
- 不允许通过刷新页面绕过过期。

## 6. 状态与场景

| 场景 | 队列 | 抽屉 | Case |
| --- | --- | --- | --- |
| 待审批 | 显示 | 可批准/拒绝 | 等待审批 |
| 已批准 | 默认隐藏，可在全部中查看 | 只读，显示审批人/时间 | 执行中或已解决 |
| 已拒绝 | 默认隐藏，可在全部中查看 | 只读，显示原因 | 审批未通过 |
| 已过期 | 默认隐藏，可在全部中查看 | 只读，显示过期时间 | 审批已过期 |
| 工具被禁用 | 待处理但标注阻断 | 批准按钮禁用并说明 | 等待人工处理 |
| Kill Switch | 全局横幅 | 批准按钮禁用 | 暂停执行 |

## 7. 响应式

- 900–1179px：抽屉宽度变为 480px；列表隐藏“等待时长”，保留风险和有效期。
- < 900px：队列改为卡片列表；点击进入全屏详情页；底部固定决定区。
- 移动端决定区必须有安全间距，避免误触。

## 8. 无障碍

- 行、抽屉和确认框均可键盘操作；Esc 关闭非提交中的抽屉。
- 倒计时使用文字更新，不使用每秒读屏播报；临近过期时只播报一次。
- 风险、临期、过期均有图标和文字。
- 抽屉打开后焦点进入标题，关闭后返回原行。
- 批准/拒绝结果通过 `aria-live` 通知。

## 9. 页面验收

- 审批人能在首屏判断优先级和临期项。
- 无需打开其他页面即可看到证据、参数、影响范围、验证和回滚。
- 批准前必须二次确认，拒绝必须填写原因。
- 非审批人、申请人本人和管理员越权均无法看到可用批准按钮。
- 并发、过期、工具禁用和 Kill Switch 都有明确阻断状态。
