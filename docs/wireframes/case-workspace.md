# Case 工作台布局底稿

> 页面：`/cases/:id`  
> 目标：一屏内看清“在聊什么、依据是什么、现在要谁做什么、流程走到哪”  
> 视觉规范：`docs/design-system.md`

## 2. 顶部区域

### 2.1 应用栏

- 高 56px，白底，底部 1px 边框。
- 左侧产品名，中部角色化导航，右侧演示身份与账户菜单。
- 导航当前项使用青绿文字 + 2px 下边线，不使用整块深色背景。
- 演示身份切换只改变当前会话身份，不改变 Case 数据。

### 2.2 Case 标题栏

- 标题 20px/600，可点击进入重命名（P1）。
- 同一行显示精确状态标签、Case ID 和请求人部门。
- 状态标签采用“图标 + 文字”，例如 `等待审批`、`审批已过期`。
- 标题过长时最多两行，不挤压状态区。

### 2.3 五阶段进度条

- 以细线连接五个节点：受理、查证、方案、审批与执行、完成。
- 当前阶段青绿实心；已完成阶段勾选；未来阶段灰线。
- 异常分支（拒绝、过期、失败）显示为当前阶段的警示子状态，不另加第六个节点。
- 进度条不承担精确状态说明，精确状态在标题和右栏。

## 3. 左栏：对话

- 宽度 320–328px，白底，右边界 1px。
- 对话区可滚动，输入区固定在底部。
- 消息不采用左右气泡对撞；用户消息用浅青底轻卡片，系统消息用白底加左边线。
- 每条消息显示角色、时间和状态；流式消息显示细光标。
- 工具步骤不伪装成用户/助手消息，以紧凑的“步骤条”插入对话流。
- 生成中显示“停止生成”；停止后显示“重新生成”。
- 输入框支持多行，Enter 发送，Shift+Enter 换行；发送后禁用重复提交。

### 3.1 步骤条示例

```text
✓ 已理解问题
✓ 已检索知识库 · 3 条依据
● 正在核对证据
```

- 步骤条 13px，左侧 16px 图标列，不使用大号卡片。
- 只显示可理解的动作，不显示模型内部推理。

## 4. 中栏：当前主卡与证据

### 4.1 主卡选择

同一时刻只突出一个主卡：

| Case 状态 | 主卡 |
| --- | --- |
| 理解/检索/诊断 | 进度卡或追问卡 |
| 已回答 | 回答卡 |
| 工单待确认 | 工单草稿卡 |
| 动作待审批 | 动作卡 |
| 执行中/完成 | 执行与验证卡 |
| 拒答 | 拒答卡 |

历史主卡折叠为摘要行，点击展开，不重复占用整屏。

### 4.2 回答卡

```text
[知识回答] VPN 证书过期                [证据充分]

结论
你的 VPN 证书已过期，需要重置证书后重新连接。

处理步骤
1. 打开 VPN 客户端，进入“证书管理”。
2. 点击“重置证书”，按提示重新登录。[1]
3. 重新连接并确认状态。[2]

证据
[1] VPN 使用与排障指南 · v3 · 第 3 页
[2] 证书过期检查记录 · 只读工具

下一步：[创建工单] [继续追问] [没帮助]
```

- “证据充分”表示有可核对来源，不是模型自评分。
- 引用编号与右侧引用面板一一对应。
- 步骤可复制；复制时保留原文，不复制 UI 文案。

### 4.3 证据面板

- 宽度与中栏一致，位于主卡下方或右侧内嵌。
- 每条引用包含：编号、标题、版本、页码/章节、精确原文、更新时间、查看原文。
- 精确原文使用 3px 浅青左边线和浅底，允许展开全文。
- 点击“查看原文”打开阅读器；阅读器覆盖中栏，保留返回按钮。
- 文档不可用时显示“来源已停用”，不删除历史引用。

### 4.4 工单草稿卡

```text
[工单草稿] 打印机无法打印                 [待确认]

分类：硬件与设备 · 打印机        建议 P2
优先级理由：单人工作受阻，影响当日交付
影响系统：办公打印系统           环境：Windows 11
报错信息：0x0000011b
建议处理人：桌面支持组 · 王工
推荐理由：技能匹配，当前负载较低

缺失信息：无
关联证据：[1] 打印机驱动排障指南

[修改字段] [确认创建工单]
```

- 字段使用可编辑字段块，不使用密集表格。
- 分类、优先级、处理人旁有“建议”标记和理由。
- 缺失字段集中显示，不能创建时解释原因。
- 确认前不创建 Ticket。

### 4.5 动作卡

```text
[高风险写操作] 重置 VPN 证书             [等待审批]

影响对象：林晓（user_1024）
理由：只读检查显示证书于今日 08:10 过期
证据：[1] 证书过期检查记录

参数
user_id    user_1024
reason     证书已过期，只读检查确认

验证方式：执行后读取 VPN 状态，确认证书有效
回滚说明：如失败，保留原证书记录并转人工处理
有效期：剩余 09:42

[查看完整审批材料]
```

- 风险用“图标 + 文字 + 左边线”，不只靠颜色。
- 非审批人只看到等待审批和剩余时间。
- 审批人看到“批准并执行”“拒绝请求”，并与信息区有明显分隔。
- P0 不允许在批准时修改参数。

### 4.6 拒答卡

```text
[无法处理] 当前请求超出权限范围

原因
员工无权查询同事的薪酬信息。

你可以：
・查看本人薪酬说明
・创建人事工单
```

- 不使用红色大错误块；这是正常安全分支。
- 不展示内部规则细节和系统 Prompt。
- 必须提供安全替代入口。

### 4.7 执行与验证卡

```text
[执行中] 重置 VPN 证书
已批准 · 审批人：陈审批 · 09:41

● 正在执行
○ 等待只读验证

[查看审批记录]
```

完成后：

```text
[已解决] 重置 VPN 证书
✓ 执行成功 · 09:42
✓ 只读验证通过 · 证书有效期至 2027-11-03
[查看时间线] [关闭 Case]
```

- 执行和验证分成两个状态，不合并成一句“成功”。
- 结果未知时显示“执行结果待确认”，不显示成功。

## 5. 右栏：状态与时间线

- 宽度 280–300px，浅雾白底，与中栏用 1px 边框分隔。
- 顶部是 Case 状态摘要：精确状态、请求人、处理人、创建时间。
- 中部是时间线：创建、检索、回答、草稿、动作、审批、执行、验证。
- 底部是关联对象：Ticket、Action、Approval、Audit 跳转。
- 时间线节点使用小圆点 + 细线，不使用彩色进度条。
- 审批事件显示操作者和决定；拒绝/过期显示原因摘要。

## 6. 关键交互

### 6.1 流式回答

- 顶部步骤先出现，token 后出现；容器预留高度，避免页面跳动。
- 引用事件到达时只更新引用面板，不重排正文。
- 滚动跟随仅在用户位于底部时启用；用户向上翻阅时不强制拉回。

### 6.2 停止与重试

- 停止只取消当前生成，不影响已提交审批。
- 停止后保留部分回答并标注“已停止”，提供“重新生成”。
- 重试生成新回答，旧回答保留在历史中。

### 6.3 审批后的跨角色更新

- 通过 `GET /api/cases/{id}/events` 更新状态。
- 员工页面收到 `approval_updated` 后刷新动作卡和状态标签。
- 页面不自动滚动到审批结果，使用状态变化提示 + 时间线新事件。

### 6.4 Case 关闭

- 关闭前提示未执行动作将失效。
- 关闭后所有写操作按钮隐藏，显示只读横幅。
- 重新打开保留历史，创建新一轮处理。

## 7. 响应式

### 7.1 900–1179px

- 右栏收起为“Case 详情”抽屉。
- 顶部保留阶段条；抽屉内保留时间线与关联对象。

### 7.2 < 900px

- 单栏顺序：对话 → 当前主卡 → 证据 → 时间线。
- 阶段条横向滚动或压缩为“当前阶段 + 展开”。
- 输入框吸底，主操作按钮全宽。
- 引用改为底部抽屉，返回时保持位置。

## 8. 页面验收

- 1280px 宽度下三栏不重叠，主阅读区可用。
- 当前主卡、精确状态、阶段和下一步操作在首屏可见。
- 引用可点击并定位；停用文档有明确提示。
- 等待审批时普通用户无批准按钮；审批人看到完整材料。
- 执行与验证结果分开显示。
- 关闭 Case 后无法继续执行未审批动作。
