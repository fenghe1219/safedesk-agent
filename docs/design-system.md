# SafeDesk 设计系统 v0.1

> 状态：设计底稿，待进入实现前评审  
> 范围：MVP，桌面端优先，兼容窄屏  
> 关联文档：`docs/ia-and-flows.md`、`docs/wireframes/case-workspace.md`、`docs/wireframes/approval-queue.md`

## 1. 设计概念

**清朗工作台**：像一张光线充足、资料摆放有序的办公桌，而不是客服聊天窗口或监控大屏。

- 清新来自雾白背景、青绿主色和充足留白。
- 专业感来自稳定布局、细边框、清晰层级和明确的安全状态。
- 可信感来自“证据可核对、动作可审批、结果可追溯”，不来自装饰。
- 克制表现在不使用渐变、玻璃拟态、持续漂浮动画和满屏彩色卡片。

### 1.1 三条界面原则

1. **证据优先**：引用、原文、参数和审批材料必须比模型措辞更醒目。
2. **下一步明确**：每个状态都要回答“现在发生了什么、谁需要决定、下一步做什么”。
3. **安全状态可读**：风险、过期、失败不能只靠颜色表达，必须同时有文字和图标。

### 1.2 不做什么

- 不做聊天气泡堆叠的 IM 界面。
- 不把 Case 的 18 个内部状态全部画成顶部进度条。
- 不用“AI 置信度”替代可核验的证据说明。
- 不用大面积红/橙背景制造紧张感。
- 不用营销页式大标题、插画和渐变装饰占据工作区。

## 2. 色彩

### 2.1 基础色

| Token | Hex | 用途 |
| --- | --- | --- |
| `canvas` | `#F6F8F7` | 页面背景，雾白 |
| `surface` | `#FFFFFF` | 卡片、面板、抽屉 |
| `surface-subtle` | `#F1F5F3` | 次级区域、表头、只读字段 |
| `primary` | `#147D70` | 主操作、焦点、当前步骤 |
| `primary-hover` | `#0F695E` | 主操作悬停 |
| `primary-soft` | `#E9F4F1` | 选中态、步骤背景、轻提示 |
| `primary-border` | `#B7DCD3` | 选中边框、引用编号边框 |
| `text` | `#17211F` | 正文与标题 |
| `text-secondary` | `#5F6F6A` | 说明、时间、辅助信息 |
| `text-tertiary` | `#87948F` | 占位符、禁用说明；不承载关键信息 |
| `border` | `#DCE5E1` | 默认分隔线、卡片边框 |
| `border-strong` | `#C3D0CB` | 输入框悬停、强调分隔 |

### 2.2 语义色

| Token | Hex | 浅色底 | 用途 |
| --- | --- | --- | --- |
| `warning` | `#A15C00` | `#FFF4E5` | 待审批、临期、缺失字段 |
| `danger` | `#B42318` | `#FDECEA` | 高风险、失败、拒绝、越权 |
| `success` | `#18794E` | `#E8F5EE` | 已解决、验证通过、审批通过 |
| `info` | `#365F73` | `#EAF2F6` | 中性提示、系统信息 |

### 2.3 使用规则

- 主色只用于主操作、焦点和当前进度，不用于普通正文。
- 危险色只用于真正的危险或失败，不用于“普通提醒”。
- 风险卡可以有一条约 3px 的语义色左边线，但风险等级必须同时显示图标和文字。
- 大面积背景保持中性；语义浅色只用于小面积标签、提示条或图标底。
- 所有文字与背景组合在实现后必须通过 WCAG 2.1 AA 对比度检查。

## 3. 字体与排版

### 3.1 字体

```text
中文/UI：Noto Sans SC, PingFang SC, Microsoft YaHei, system-ui, sans-serif
数字/ID：IBM Plex Mono, SFMono-Regular, Consolas, monospace
```

- 不加载装饰性字体，不使用全大写英文标题。
- 数字、参数哈希、Case ID、时间使用等宽数字：`font-variant-numeric: tabular-nums`。
- 中文正文不加字间距，不使用过细字重。

### 3.2 字号层级

| 角色 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面主标题 | 20/28 | 600 | Case 标题、页面标题 |
| 区块标题 | 16/24 | 600 | 卡片标题、抽屉标题 |
| 正文 | 14/22 | 400 | 主要内容、表格正文 |
| 强调正文 | 14/22 | 500 | 结论、字段名、按钮 |
| 辅助 | 13/20 | 400 | 说明、推荐理由、时间 |
| 标签 | 12/18 | 500 | 状态、分类、风险标签 |
| 微型 | 11/16 | 500 | 参数键、ID、计数 |

阅读型卡片正文每行控制在 36–42 个中文字符，避免横跨整屏。

## 4. 间距、网格与布局

### 4.1 间距

使用 4px 基数：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。

- 页面外边距：桌面 24px，平板 16px，手机 12px。
- 卡片内边距：常规 20–24px，紧凑表格 16px。
- 区块间距：24px；表单字段间距：16px。
- 图标与文字：8px；标签内部：6px。

### 4.2 应用外壳

- 顶部应用栏高 56px，包含产品标识、角色化导航、演示身份切换和账户菜单。
- 内容区铺满宽度，但工作台内部按三栏布局约束。
- 不使用常驻左侧大侧栏，避免压缩 Case 工作台的中间阅读区。

### 4.3 Case 工作台断点

| 宽度 | 布局 |
| --- | --- |
| ≥ 1440px | `328px / minmax(560px, 1fr) / 300px`，栏间距 16px |
| 1180–1439px | `288px / minmax(0, 1fr) / 264px` |
| 900–1179px | 收起右栏为“Case 详情”抽屉，保留 `288px / minmax(0, 1fr)` |
| < 900px | 单栏，顺序为对话 → 当前卡片 → 证据 → 时间线；输入框吸底 |

中间内容最大阅读宽度 760px；证据阅读器可以临时扩展到全宽。

## 5. 形状、边框与阴影

| 元素 | 圆角 | 说明 |
| --- | --- | --- |
| 按钮、输入框 | 8px | 不做大胶囊 |
| 卡片、面板 | 10px | 主要信息容器 |
| 抽屉、模态框 | 12px | 仅外侧圆角 |
| 状态标签 | 999px | 小尺寸胶囊，仅用于状态 |
| 引用编号 | 6px | 小而清晰 |

阴影只用于浮层，不用于普通卡片：

- `shadow-1`：`0 1px 2px rgba(23, 33, 31, 0.04)`，用于卡片。
- `shadow-2`：`0 8px 24px rgba(23, 33, 31, 0.08)`，用于抽屉和模态框。
- 普通层级优先使用 1px 边框和背景差异，不堆叠阴影。

## 6. 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 悬停、按压 | 120ms | ease-out |
| 展开、折叠 | 160ms | ease-out |
| 抽屉 | 220ms | cubic-bezier(0.2, 0.8, 0.2, 1) |
| 模态框 | 240ms | cubic-bezier(0.2, 0.8, 0.2, 1) |

- 只动画透明度、位移和尺寸变化，不做持续漂浮、发光或弹跳。
- 流式回答保持容器高度稳定，不逐 token 播放动画。
- 审批结果和状态变化必须有非动画反馈，例如文字变更和焦点移动。
- 遵循 `prefers-reduced-motion`，关闭位移和缩放动画。

## 7. 图标

- 使用 1.5px 描边的线性图标，常用尺寸 16px；导航 20px。
- 图标不能单独承载关键含义；风险、删除、审批等必须有文字说明。
- 语义固定：盾牌=治理/权限，三角感叹号=风险，时钟=有效期，勾选圆=验证通过，文档=证据。

## 8. 核心组件

### 8.1 按钮

| 类型 | 用法 | 视觉 |
| --- | --- | --- |
| Primary | 当前页面唯一主操作 | 青绿底、白字 |
| Secondary | 次要操作 | 白底、细边框、墨色字 |
| Ghost | 低优先级、返回、展开 | 透明底、悬停浅灰 |
| Danger | 拒绝、取消敏感动作 | 白底红字红边；只有真正不可逆操作才使用红底 |

- 常规高度 36px，紧凑 32px，大操作 40px。
- 同一屏最多一个 Primary；审批抽屉的“批准并执行”是主操作，“拒绝”是 Danger 次操作。
- 加载时保留按钮宽度，显示进度并禁用重复提交。

### 8.2 输入与表单

- 输入框高度 36px，文本域最小 96px。
- 标签在上方，13px/500；帮助文字 12px；错误文字 12px，带图标。
- 只读字段使用 `surface-subtle` 背景，不伪装成可编辑输入框。
- 工单草稿的字段编辑采用“字段块”而不是密集表格。
- 错误必须定位到具体字段，同时在表单顶部提供摘要。

### 8.3 状态标签与风险标签

- 状态标签：小圆点或图标 + 用户可读文字，例如“等待审批”“审批已过期”。
- 风险标签：`高风险写操作`、`低风险只读`，同时显示盾牌或三角图标。
- 标签颜色不能是唯一区别；相同颜色在不同场景也必须保持语义一致。
- 禁止把内部枚举直接展示给用户，例如 `AWAITING_APPROVAL`。

### 8.4 信息卡

所有主卡片遵循同一结构：

```text
[类型标签] [标题]                         [状态/操作]
[摘要或核心内容]
[证据、参数、字段或步骤]
[底部：来源、时间、下一步操作]
```

- 一屏只允许一张“当前主卡”，其余内容降级为摘要或折叠。
- 回答卡偏阅读；工单卡偏表单；动作卡偏审批材料，三者视觉上必须可区分。
- 卡片底部操作区使用细分割线与正文分离。

### 8.5 引用

- 行内引用为 `[1]` 形式的小编号，颜色为主色，可点击。
- 引用面板按编号排序，显示标题、版本、页码/章节、精确原文、更新时间。
- 精确原文使用左侧 3px 浅青边线和浅底，不使用斜体。
- 文档不可用时显示“来源已停用”，仍保留历史引用信息。

### 8.6 时间线

- 垂直细线 + 小节点，节点颜色对应事件语义。
- 事件包含：时间、标题、操作者、简短结果；详细 payload 折叠。
- 最近事件默认展开，较早事件按组折叠。
- 时间显示规则：今天显示 `HH:mm`，更早显示 `MM-DD HH:mm`，悬停显示完整时间。

### 8.7 抽屉与模态框

- 审批详情使用右侧抽屉，宽 520–600px，头部和底部固定，中间滚动。
- 批准前使用二次确认模态框，必须复述动作、影响对象、风险和有效期。
- 拒绝使用小模态框，原因必填，提供常用原因但允许自由输入。
- 抽屉打开时焦点移入，关闭后回到触发元素；支持 Esc 关闭，但敏感操作未提交时不丢失已填内容。

### 8.8 表格与列表

- 行高 44px，表头 12px/500，正文 13px。
- 使用横向细线和留白分组，不使用斑马纹。
- 关键列固定：动作/工单标题、状态、风险/优先级、负责人、时间。
- 窄屏表格改为卡片列表，不用横向滚动承载关键操作。

### 8.9 空、加载、错误状态

- 空状态说明“为什么为空”和一个明确下一步。
- 加载状态显示当前步骤，而不是只有旋转图标。
- 部分成功必须分开显示成功项和失败项。
- 错误使用内联提示 + 重试入口；权限不足显示可返回的安全路径。

## 9. 文案规则

- 语气平静、具体、可执行，不卖萌、不感叹、不拟人化。
- 系统称“系统”，不以“我”自称；按钮使用“动词 + 对象”。
- 拒答先说明边界，再给安全替代，例如“当前账号无权查看他人薪酬信息。你可以查看本人薪酬说明，或创建人事工单。”
- 审批文案必须说明“会发生什么”，不使用“确定吗？”这种空泛确认。
- 时间、版本、参数和风险必须写清楚；不使用模糊的“很快”“可能没问题”。
- 示例按钮：`创建工单`、`查看原文`、`批准并执行`、`拒绝请求`、`重新尝试`。

## 10. 无障碍

- 正文与背景对比度至少 4.5:1，大字号至少 3:1。
- 所有交互元素有可见焦点环，焦点顺序与阅读顺序一致。
- 状态变化通过 `aria-live` 通知；流式回答使用节流后的礼貌播报。
- 风险、成功、错误不能只靠颜色区分。
- 抽屉和模态框使用焦点陷阱；关闭后恢复焦点。
- 支持 200% 缩放和键盘操作；关键页面在 1280px 宽度可用。
- PDF 阅读器提供页码输入和文本定位替代方案。

## 12. 设计验收清单

- 主操作在同一视图中唯一且明确。
- 当前 Case 阶段、精确状态和责任人可一眼识别。
- 引用、参数、风险和执行结果均可读、可展开、可追溯。
- 审批按钮与普通操作有明显安全分隔。
- 窄屏不丢失关键状态，不出现只能横向拖动才能完成的主流程。
- 风险/成功/失败不只依赖颜色。
- 流式输出不造成布局跳动。
- 页面与组件符合本文件的色彩、字号、间距和动效 token。
